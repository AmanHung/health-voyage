# 第三階段：個人活動目標與進度

## 使用方式

- 首頁在每日任務下方增加「我的活動目標」卡，顯示已保存步數、目標環形進度與本週達標足跡。
- 管理員於名冊選擇「設定活動目標」，填入照護團隊與個案討論後的步數。既有個案不會自動獲配任何步數目標。
- 首次設定當日生效；後續調整或暫停從伺服器日期的隔日生效。相同生效日最後保存的版本有效，全部修改歷程保留。
- 個案重新登入讀取帳號目標；目標由照護團隊設定，個案修改暱稱不能改寫目標。

## 計算邊界

- 進度只讀取同日最新保存的步數紀錄，不累加修訂、不將運動分鐘換算成步數。
- 尚無紀錄與已記錄零步分開呈現。未設定、暫停目標及未來日期不計為達標。
- 達標足跡依當日有效目標計算；後續新目標不追溯套用過去日期。
- 環形進度上限為 100％，不因超額活動增加獎勵。航程、紀錄日與既有參與徽章維持原本計算。
- 步數只反映已確認的活動紀錄，不推論疾病控制或心血管風險。此階段不提供預設運動處方。

## 儲存與部署

- 私人 Patients JSON 新增 activityGoals 陣列，儲存版本 ID、步數／暫停、生效日期、操作者、時間與重送辨識資訊；既有工作表不需改欄位或遷移。
- 患者回應只回傳該個案目標的 ID、步數與生效日期；操作稽核另記於 Audit。
- admin.activityGoal 由伺服器驗證管理員、個案有效性、整數範圍，並在鎖定內檢查版本衝突與重送。技術輸入範圍不是建議活動量。
- 先建置並更新既有 Google Apps Script 部署，再發布 GitHub Pages 前端。GET 版本 2 與 activityGoals 能力標記用於確認後端相容性。

## 驗證

- 自動測試覆蓋個案隔離、禁止患者設定目標、偽造個人設定、保存後重新讀取、重送、衝突、停用個案、稽核歷程、生效日期、暫停、零值／缺值、修訂與跨週邊界。
- 靜態元件渲染檢查未設定、達標與暫停文字，以及管理員空白預設欄位。
- 實際 LINE 手機互動與照護團隊訂定活動目標的臨床流程仍需使用者驗收。

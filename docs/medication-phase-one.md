# 個人用藥清單與逐項回報

## 操作

管理員由「個案名冊 → 管理用藥」開啟。搜尋院內藥品或手動新增院外藥，核對規格、劑型、途徑、用量、使用星期、起訖日期及時段。用量預設空白，必須由藥師填入。先預覽，再確認發布。草稿僅留在目前畫面，取消、離開或重新整理會捨棄未發布編輯。

清單使用臺灣時間，生效時間必須晚於伺服器現在時間。新版本從生效時間起取代先前所有安排（包含尚未生效的變更），過去各時段仍使用當時有效的版本。同一藥品以多時段表示，不能重複新增使用中的相同品項。可停用、移除品項或發布空清單；這些操作不刪除舊版本。

個案從首頁「用藥回報」查看清單。每項每次獨立選擇已服用、未服用或有疑問，再儲存；未服用與有疑問可選填補充。尚未到預定時間的固定用藥不能提前回報。可補填最近 30 天。需要時使用的藥按實際時間回報，同藥同分鐘為同一次，可修改但不重複增加。需要時用藥不列入固定用藥分母。

當天沒有固定排程，可明確確認「今日沒有固定用藥」。不能用此確認略過既有固定排程。未回報與未服用分開保存。部分回報可累積參與日，但不把每日三任務中的用藥任務標為完整；回報所有固定時段才完成該任務，未服用及有疑問均算如實回報。

管理後臺及健康紀錄提供逐項回報明細。較完整的問題處理佇列、藥師處理註記、週月統計與 LINE 提醒屬後續階段。

## 藥師權限

管理員可在個案用藥管理底部「指派此個案的藥師」填入 Google 帳號，每行一位。指派後該藥師可用既有 Google 登入入口查看受指派個案的用藥清單與回報，並發布清單。藥師不能讀取運動、飲食、私人上傳照片，不能刪除個案、建立個案或自行指派權限。移除指派、停用或刪除個案會立即阻擋後續存取，包含已登入的快取身分。

此版本只新增指派功能；部署不會替任何真實帳號自動授權，也不建立真實處方。

## 資料與串接

- `MedicationPlans` 在既有私人健康紀錄試算表中新增，首次成功發布時於鎖內建立；未使用功能前不需要資料遷移。每列保留一份完整清單版本、操作者與生效時間。
- `Records` 延用每日每類最新版本規則。每次逐項儲存會追加當日用藥快照，內含每次回報的清單版本、藥名、規格、用量、服法及時間。舊列不覆寫，既有刪除與復原流程適用整日用藥紀錄。
- 舊版每日總回報保持原樣，不推算成逐項服用；有排定清單的日期不能再用舊 API 覆蓋逐項回報。
- 用操作編號保護重送，以目前每日紀錄與清單版本比對防止覆蓋。藥名、用量等由後端已發布清單決定，不信任個案送入的欄位。
- 沿用 Formulary 已公開的 Google CSV 與 Cloudinary 藥品代碼圖片來源。只在藥師開啟編輯時載入公開目錄，20 秒逾時可重試或手動建檔。沒有圖片仍可建立、顯示與回報，圖片請求不附個案資料或 referrer。
- 規格、用量與服法由藥師依處方維護，不自動套用藥典的一般用法。藥品外觀更新不會自動改動個案清單。
- 單份清單最多 20 項、60 個固定時段；每日含需要時用藥最多 80 筆回報。延用試算表列數上限，每次修訂會增加列數。依個案編號先篩選讀取，並未完成大量收案的容量與配額驗證；擴大前仍需監測與資料庫遷移規劃。

## 驗證與發布

使用虛構個案及 Google 服務替身測試權限、重送、併發、當日換藥、指定星期、起訖日期、需要時用藥、零固定用藥、刪除復原及舊紀錄保留。介面渲染測試檢查劑量、缺圖、未服用與未回報的區別，不等同真實手機與帳號驗收。

先建置及部署 Apps Script（GET version 4、`medicationPlans` 能力），再發布前端。維持既有端點、私人試算表及 LINE／Google 驗證，不增加 OAuth 權限。
